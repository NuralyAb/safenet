# SafeNet KZ — методика: признаки и расчёт риска

> **Ключевой принцип.** Система не объявляет схему незаконной. Она находит **признаки возможного
> нарушения**, считает уровень риска и показывает, почему материал помечен. Законность конкретной
> схемы проверяет специалист с учётом законодательства РК.

Код методики: [`backend/app/services/safenet/`](../backend/app/services/safenet/).

## 1. Конвейер

```
материал (пост / скриншот / эфир / видео / экспорт группы)
  │  извлечение текста: подпись, речь (STT), текст на кадре (OCR), визуальные теги
  ▼
normalize.py   — «виды» текста против обфускации
  ▼
detector.py    — признаки: словарь RU/KZ/translit + числовые экстракторы + LLM-помощник
  │              (каждый признак = дословная цитата + источник + способ маскировки)
  ▼
scoring.py     — детерминированный балл по каждому треку → гейты → смягчения → уровень
  ▼
group.py       — для групп: шаблонные сообщения, поток «отзывов», организатор/кураторы
  ▼
очередь «Материалы» (риск × охват) → решение аналитика · граф связей (Neo4j)
```

LLM **никогда не ставит балл** (инвариант проекта). Он может только предложить признак с цитатой.
Цитата должна дословно встречаться в тексте, иначе находка отбрасывается: так отсекаются галлюцинации.

## 2. Против маскировки (`normalize.py`)

Каждый шаблон проверяется на нескольких «видах» одного текста. Аналитик видит, каким способом
признак был скрыт.

| Вид | Что снимает | Пример |
|---|---|---|
| base | регистр, `ё→е`, невидимые символы, стилизованный Unicode (NFKC) | `𝓿𝓪𝓿𝓪𝓭𝓪 → vavada` |
| deobf | латиница-двойник в кириллице, цифры и символы вместо букв | `KAЗИНО`, `к@зин0 → казино` |
| collapsed | разрядка букв | `К А З И Н О`, `к.а.з.и.н.о` |
| translit | латиница → кириллица (RU и казахская латиница) | `vlozhi … poluchi`, `utys` |
| emoji | эмодзи → слова | `🎰 → казино`, `💸 → деньги` |

Казахские буквы приводятся к русским двойникам (`қ→к, ұ/ү→у, ө→о, ә→а, ғ→г, ң→н, і→и`). Один шаблон
ловит и «тегін», и «тегин», то есть текст с казахской раскладкой и без неё.

## 3. Признаки по трекам и веса

`ключевой` — без него трек не может дать высокий балл (см. гейты).

### Трек 1 — розыгрыши с платным участием

| Признак | Вес | Примеры (RU / KZ) |
|---|---|---|
| **Платное участие** (ключевой) | 40 | «взнос», «номер = 1000 тг», «купи билет», «вход 500», «кто скинет по 500» / «қатысу ақылы», «жарна», «билет сатып ал», «бағасы 500₸» |
| Случайный выбор победителя | 20 | «рандомайзер», «колесо», «жеребьёвка», «в прямом эфире выберем» / «кездейсоқ», «жеребе» |
| Доход организатора | 20 | «продажа слотов», «осталось 15 номеров», «все номера проданы», «50 мест по 1500» / «орын қалды» |
| Перевод на личную карту / Kaspi | 15 | «перевод на Kaspi», номер карты (проверка Луна), «каспиге аударыңыз» |
| Тема розыгрыша | 10 | «розыгрыш», «лотерея», «гив» / «ұтыс» («приз», «победитель» — слабый контекст) |
| Серия розыгрышей | 10 | «розыгрыш №27», «каждую пятницу» / «апта сайын» |
| Механика бесплатного конкурса (смягчение) | ×0.5 | «подпишись + лайк + отметь друга», «бесплатно» / «тегін», «жазылыңыз» |

| Признак | Вес | Примеры |

### Числовой анализ доходности (`numeric.py`)

В пирамидальных текстах часто нет «страшных» слов: признак кроется в арифметике.

* **«Вложи X → получи Y»**: сумма рядом со словом вложения, затем большая сумма рядом со словом
  получения (`вложи/внёс/салсаңыз … получи/забираешь/аласыз`). При Y/X ≥ 1.3 это признак. Отношение
  ≥ 2 или короткий срок дают полную силу.
* **Периодическая выплата меньше вклада**: «вложила 5000, вывожу по 1500 каждую неделю» = 30% в неделю.
* **Процент с периодом**, приведённый к ставке за единицу периода («120% за 2 месяца» = 60%/мес).
  Пороги нереалистичности: **≥0.5% в день, ≥2% в неделю, ≥8% в месяц, ≥40% годовых**. Ориентир —
  депозиты в банках РК: ≈14–16% годовых.
* Банковский контекст (КФГД/КДКҚ, капитализация, «под 16%», «годовых») не считается обещанием.
* **Номера карт**: 16 цифр с проверкой Луна. В интерфейсе показываются только BIN и последние 4 цифры
  (минимизация персональных данных).

## 4. Расчёт балла

```
балл_трека = Σ вес(признака) × сила(признака)
             сила: 1.0 — точное правило / число;  0.8 — LLM с проверенной цитатой;  0.5 — слабое правило
затем ГЕЙТЫ (ограничение сверху) и СМЯГЧЕНИЯ (множитель)
итоговый балл = max по трекам;   трек материала = argmax
уровень: высокий ≥ 65,  средний ≥ 40,  низкий < 40
«помечено для ручной проверки» = средний или высокий
```

**Гейты против ложных срабатываний** («главная сложность» каждого трека):

| Трек | Условие | Действие |
|---|---|---|
| Розыгрыш | нет темы розыгрыша | ≤ 25: оплата относится к другому (семинар, предоплата) |
| Розыгрыш | нет признака платного участия | ≤ 25: обычный конкурс |
| Розыгрыш | взнос + приз, но нет случайности и перевода на личную карту | ≤ 35: турнир или конкурс мастерства |
| Розыгрыш | механика бесплатного конкурса без платы | ×0.5 |
| Казино | нет игровой лексики или бренда | ≤ 20; при нативной рекламе со ссылкой ≤ 50 |
| Казино | игры упомянуты без продвижения (ссылки, промокода, призыва) | ≤ 35: новости, кино |
| Казино | оператор найден в реестре лицензий | ×0.5: проверить правила рекламы, а не деятельность |
| Пирамида | нет обещания доходности и дохода от привлечения | ≤ 30; при реферальном сборе денег ×0.8 |
| Все | текст предупреждает о мошенничестве (новость, полиция, АФМ, «сақ болыңыз») и в нём нет ссылки, карты, телефона, промокода или призыва | ×0.4 |

Каждая поправка записывается в разбивку отдельной строкой с отрицательным вкладом. Поэтому
**Σ вкладов = итоговый балл**, и каждый пункт прослеживается до `evidence_id` (SHA-256 материала
в WORM-хранилище).

## 5. Сеть и масштаб

* Идентификаторы (Kaspi-телефон, маскированная карта, промокод, короткая ссылка, Telegram, домен)
  пишутся в граф Neo4j. Аккаунты, собирающие деньги на один номер или раздающие один промокод,
  объединяются в сеть. Louvain выделяет сообщества, betweenness — вероятных организаторов.
  Совпадения со схемами добавляют признак «связи» (до +10).
* Правила работают **≈400–900 материалов/с на одно ядро** без LLM (замер в `docs/METRICS.md`).
  Это ≈35–75 млн материалов в сутки на ядро до горизонтального масштабирования. LLM включается только
  как помощник: настройка `safenet_llm_assist`, в проде — self-hosted модель.
* Конвейер Celery (collect → process → fingerprint → score) масштабируется добавлением воркеров.
  Temporal используется для долгих расследований.

## 6. Этика и данные

* Для разработки и оценки используются **только синтетические данные** (`backend/app/services/safenet/data/`).
  Во внешние API разрешено отправлять только синтетику (инвариант проекта).
* Номера карт маскируются. Роли в группах («организатор», «куратор») помечены как **кандидаты**.
  Аналитик подтверждает или отклоняет каждое срабатывание: «Передать специалисту», «Наблюдать»,
  «Ложное срабатывание». Все действия пишутся в журнал аудита с хеш-цепочкой.
* Система не содержит функций, помогающих организовывать схемы. Она только находит признаки и
  объясняет их.
