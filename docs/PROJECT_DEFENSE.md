# SafeNet KZ — Защита проекта: полное описание функционала и демо-тест

**SafeNet KZ (AI Platform for Fraud Intelligence & Social Media Investigation)** — on-prem
платформа для выявления и расследования сетей финансового мошенничества в соцсетях.
Профиль применения: гос/правоохранительный (АФМ — Агентство по финансовому мониторингу).

Главная идея: **«от одного видео — к целой мошеннической сети»**. Система не просто
помечает отдельный ролик, а раскручивает за ним инфраструктуру (кошельки, telegram-
каналы, домены, связанные аккаунты) и показывает организаторов схемы.

---

## 1. Проблема и решение

**Проблема.** Мошеннические инвест/казино-схемы массово рекламируются в YouTube/TikTok/
Instagram/Telegram. Ручной мониторинг не масштабируется; отдельная блокировка ролика не
бьёт по сети, которая просто перезаливает контент с новых аккаунтов.

**Решение.** Конвейер: автоматический сбор → мультимодальный AI-анализ (речь, текст на
экране, визуальные маркеры, NLP) → детерминированная риск-оценка → сшивание в граф сети
по «твёрдым» идентификаторам → выявление сообществ и организаторов → доказательная база.

**Стек:** FastAPI · Celery · PostgreSQL · Neo4j (GDS) · Qdrant · Redis · MinIO · Temporal ·
vLLM (целевой self-hosted) · React + TypeScript + TanStack Query + Cytoscape.js.

**Провайдер-абстракция AI** (`app/services/ai/`): прототип работает через внешние API
(OpenAI/Anthropic) на **публичных/синтетических** данных; продакшен переключается на
`local` (self-hosted vLLM/Whisper) одним конфигом, без переписывания пайплайна.

## 3. Полный функционал

### 3.1 Три killer-фичи

**(1) Scam Fingerprint — «отпечаток схемы».**
Композитный отпечаток контента = «мягкие» сигналы (текстовые эмбеддинги речи+субтитров+
OCR) + «твёрдые» идентификаторы (кошельки, telegram, домены). Хранится в Qdrant. Поиск
похожих + кластеризация (union-find) объединяет ролики разных аккаунтов в одну `ScamSchema`
— так видно масштабирование одной схемы по множеству аккаунтов.

**(2) Fraud Graph — граф мошеннической сети.**
Neo4j + GDS. Аккаунты, кошельки, telegram-каналы, домены — узлы; связи строятся из
извлечённых идентификаторов. Алгоритмы: **Louvain** (сообщества = организованные сети),
**betweenness centrality** (центральные узлы = вероятные организаторы). Связи «один человек»
(`SAME_PERSON`) — кандидаты с confidence, пока аналитик не подтвердит (human-in-the-loop).

**(3) AI Investigator — авто-расследование.**
Durable-workflow на Temporal: по цели собирает факты из Postgres/Neo4j, считает
детерминированный риск, LLM пишет **нарратив строго по фактам** (число не назначает), и
формирует доказательный отчёт.

### 3.2 Риск-движок (ядро, `risk_engine.py`)
- **Детерминированный и объяснимый.** 6 факторов из ТЗ с фиксированными весами (сумма 100):
  financial_promises 25, referral_structure 20, known_scheme_repetition 20,
  suspicious_links 15, gambling_content 10, infra_anonymity 10.
- Балл = Σ(вес × сила фактора), сила 0..1. Уровни: LOW<40, MEDIUM 40-64, HIGH 65-84, CRITICAL≥85.
- **Каждый балл трассируется к `evidence_id`** — отчёт защитим на ручной/юридической проверке.
- **Инвариант: LLM извлекает факты, число считает движок.** Промпт нарратива прямо запрещает
  скоринг.
- Два режима: по аккаунту (roll-up, бинарные силы) и per-video (градуированные силы +
  усилители «агрессивный призыв», «скрытое вовлечение»).

### 3.3 Пайплайн анализа видео
collect → **evidence (WORM + SHA-256)** → ffmpeg (аудио + несколько кадров) → Whisper
(распознавание речи) → OCR (текст с кадров) → vision-теги (казино/слоты) → LLM-извлечение
признаков → текстовый эмбеддинг → fingerprint (Qdrant) → граф (Neo4j) → риск.
- **Многокадровость:** маркер, мелькнувший в любом месте ролика, будет пойман.
- **Ad-hoc анализ:** «Анализ видео» по ссылке или загрузкой файла (`/analyze/url`, `/analyze/file`).

### 3.4 Источники (коллекторы)
- **YouTube** — yt-dlp, вкладки videos + shorts.
- **TikTok** — yt-dlp + резолвер/сессионный cookie.
- **Instagram** — yt-dlp + cookie залогиненной сессии (анонимно блокируется).
- **Telegram** — скрейп публичного веб-превью `t.me/s/<канал>` (без API/логина): текст постов
  → пайплайн → риск + идентификаторы.
- **WhatsApp** — НЕ поддерживается (E2E-шифрование), зарегистрирован и падает с объяснением.
- Каждый источник проходит **SSRF-гард** (allowlist хостов, блок приватных/metadata-адресов).

### 3.5 Постоянный мониторинг
Watchlist (аккаунты + ключевые слова). Celery beat периодически обходит активные цели:
аккаунты перевыкачиваются, по ключевым словам **проактивно** ищется новый контент. Свой
интервал и лимит на цель. Уведомления о новых находках.

### 3.6 Проверка по реестру лицензий
Сверка домена/хендла/названия с реестром лицензированных операторов. Если игорный/инвест-
оператор не в реестре → признак **нелицензионной (незаконной)** деятельности (+ к риску по
`infra_anonymity`). Источники: env-allowlist, live-клиент API регулятора, и **импорт реестра
АРРФР** (таблица `licensed_entity`, CSV-импорт, статус active/suspended/revoked — отозванная
лицензия не считается действующей). Ручная проверка в UI + авто-проверка в пайплайне.

### 3.7 Money Flow (on-chain)
Трассировка публичного блокчейна: аккаунт → кошелёк → биржа (Etherscan API V2, исходящие
переводы, тэги известных бирж). Намеренная **граница**: связь «кошелёк → банковский счёт»
вне публичного on-chain — это данные АФМ, не наши. Мост, а не вся цепь.

### 3.8 Доказательная база и безопасность
- **Chain of custody:** оригиналы хешируются (SHA-256) и кладутся в WORM-бакет (MinIO) в
  момент сбора; записи Evidence.
- **Append-only аудит:** хеш-цепочка, INSERT-only на уровне БД (триггер Postgres).
- **Аутентификация:** argon2 + TOTP (MFA), JWT access/refresh, RBAC (analyst/supervisor/admin),
  rate-limit на логин.
- **Биометрия** (face/voice эмбеддинги) — спец-категория, шифруется на хранении; доступ от
  supervisor+.
- **Security-гейт в CI:** SAST + секрет-скан + проверка зависимостей на каждый PR.

### 3.9 Очереди аналитика
- **Триаж** (аккаунты) и **Материалы** (отдельные видео) — отсортированы по риску (Материалы:
  риск × охват). Аналитик ставит диспозицию (эскалировать / наблюдение / отклонить); решение
  переживает повторное расследование.
- **Действия:** подтверждение `SAME_PERSON` (human-in-the-loop), пересборка кластеров схем.

## 4. Ключевые инженерные принципы (сильные стороны на защите)

1. **Объяснимость и детерминизм риска.** ИИ не «чёрный ящик, выдающий балл» — он извлекает
   факты, а балл считает прозрачный движок с трассировкой к доказательствам. Это критично
   для правоохранительного применения (балл нужно защитить в суде).
2. **Chain of custody с первой секунды.** Доказательства неизменяемы и хешированы.
3. **Human-in-the-loop.** Чувствительные выводы (тот же человек) — кандидаты до подтверждения.
4. **On-prem-first.** Данные не покидают периметр; внешние API — только на прототипе и только
   на публичных/синтетических данных, через swappable-абстракцию.
5. **Инженерная зрелость.** 246 backend-тестов + фронт-тесты, CI security-гейт, миграции,
   идемпотентность, dead-letter, retries в пайплайне.

## 5. Демо-сценарий защиты («тест» — что показать вживую)

> Предусловие: `docker compose up`, миграции применены, задан `OPENAI_API_KEY`; для демо
> реестра — импортирован образец CSV; для Instagram/TikTok — задан cookie (по желанию).

1. **Вход.** Логин аналитика: пароль + TOTP-код → JWT → защищённый дашборд. *(показать MFA и
   RBAC: supervisor-действия скрыты у обычного аналитика.)*
2. **Анализ реального видео.** Вкладка «Анализ видео» → вставить ссылку YouTube на инвест/
   казино-ролик → система прогоняет речь (Whisper), текст с кадров (OCR), визуальные теги,
   NLP-признаки → показывает **риск-оценку с разбивкой по факторам** и извлечённые
   идентификаторы (кошельки, telegram, домены).
3. **Проверка лицензии.** Ввести домен оператора → «не в реестре» (красный) = признак
   незаконной деятельности; ввести лицензированный (`profit-x.kz`) → «в реестре» (зелёный).
4. **Расширение сети из видео.** У извлечённого telegram-канала нажать **«Мониторить»** →
   канал добавлен в наблюдение и в граф; на обходе его публичные посты собираются и
   анализируются так же.
5. **Граф сети.** Вкладка «Граф» → сеть из Neo4j; подсвечены сообщество и центральный узел
   (вероятный организатор). Показать `SAME_PERSON?` как кандидата.
6. **Money Flow.** Ввести аккаунт → трассировка кошелёк → биржа (Etherscan), плашка границы.
7. **Материалы/Триаж.** Лента видео по убыванию риска (× охват) → поставить диспозицию.
8. **Доказательная база.** Показать, что оригинал в WORM с SHA-256 и запись в append-only
   аудите (хеш-цепочка).
9. **Расследование.** «Расследовать @аккаунт» → детерминированный отчёт + нарратив LLM по
   фактам + счётчики сети.

**Ключевой нарратив демо:** одно видео → риск с доказательствами → его идентификаторы →
сеть и организатор → деньги к бирже → постоянный мониторинг. Это и есть «от ролика к сети».

## 6. Тестирование и качество

- **Backend:** 246 тестов (unit + contract). Внешние вызовы в CI замоканы (`respx`) — CI
  бесплатный, стабильный, детерминированный. Integration-тесты (живые docker-сервисы) —
  по флагу.
- **Frontend:** `tsc` + `vite build` + vitest.
- **CI security-гейт** (`security-gate`): SAST (уязвимости кода), секрет-скан, проверка CVE
  зависимостей — на каждый PR/пуш в main; падает на critical/high.
- **Пирамида тестов:** unit (чистая логика: risk/fingerprint/extract/clustering) → contract
  (AI-провайдеры, коллекторы на моках) → integration → smoke (ручной, перед демо).
- **Принцип регрессий:** ни один прошлый тест не должен покраснеть при новой фиче.

## 7. Вероятные вопросы комиссии и ответы (Q&A)

**В1. Балл риска выдаёт нейросеть? Как вы её объясните в суде?**
Нет. Нейросеть только **извлекает факты** (есть ли обещание прибыли, реферальная схема,
лицензия, азартный контент). Балл считает **детерминированный движок** по фиксированным
весам, и каждый вклад трассируется к `evidence_id`. Один и тот же вход → один и тот же балл,
полностью воспроизводимо и объяснимо.

**В2. Почему внешние API (OpenAI), если требование — on-prem?**
Это ограничение **прототипа** (нет локального GPU). Весь AI идёт через провайдер-абстракцию;
через внешние API — **только публичные/синтетические** данные. В продакшене `AI_PROVIDER=local`
переключает на self-hosted vLLM/Whisper без изменения пайплайна. Реальные дела/биометрия —
никогда наружу.

**В3. Как вы не дублируете и не теряете данные при сборе?**
Контент-адресация по SHA-256 (идемпотентность — повторный прогон не создаёт дублей), retries
с backoff на транзиентные сбои, dead-letter на терминальные. Каждая стадия валидирует контракт
входа.

**В4. Что мешает злоумышленнику подсунуть вредоносную ссылку (SSRF)?**
SSRF-гард: схема только http/https, хост из allowlist, блок приватных/loopback/link-local и
metadata-адреса (169.254.169.254). Плюс сетевая изоляция processing-воркеров в продакшене.

**В5. Как determine «тот же человек»? Не будет ли ложных обвинений?**
Связи `SAME_PERSON` — **кандидаты** с confidence; пока аналитик-supervisor не подтвердит, это
не факт (на графе — пунктир `SAME_PERSON?`). Авто-подтверждение запрещено инвариантом.

**В6. Как считается «похожесть схем» (fingerprint)?**
Композитно: косинусная близость текстовых эмбеддингов (мягкий сигнал) + совпадение твёрдых
идентификаторов (кошелёк/telegram/домен). Совпадение твёрдого идентификатора — сильнейший
сигнал «одна схема»; кластеризация union-find собирает их в `ScamSchema`.

**В7. Telegram/Instagram же закрыты — как собираете?**
Telegram — публичное веб-превью `t.me/s/<канал>` (без API/логина). Instagram/TikTok — через
cookie авторизованной (тестовой) сессии, т.к. анонимно блокируются. Везде — только публичный
контент; приватные каналы потребуют MTProto-доступа (отдельный путь).

**В8. Money Flow доводит до банковского счёта?**
Нет, и это **намеренно**. Мы трассируем публичный on-chain до биржи. Связь «кошелёк → счёт»
вне публичного блокчейна — это данные АФМ. Мы — мост и дополнение, не замена их систем.

**В9. Откуда данные о лицензиях?**
Реестр регулятора (АРРФР: finreg.kz / data.egov.kz). Импортируется в таблицу `licensed_entity`
со статусом; отозванная/приостановленная лицензия не считается действующей. Сверка — по
домену/хендлу, который реально встречается в контенте.

**В10. Целостность доказательств — как гарантируете?**
Оригинал хешируется SHA-256 и кладётся в WORM-бакет при сборе. Аудит — append-only,
хеш-цепочка, INSERT-only на уровне БД (триггер). Подмена/удаление выявляются.

**В11. Масштабируемость?**
Сбор и обработка — асинхронные Celery-воркеры (раздельные очереди collect/process/fingerprint),
кап параллелизма под лимиты провайдера. Векторный поиск — Qdrant, граф — Neo4j/GDS. Долгие
расследования — durable Temporal-workflow (переживают перезапуски).

**В12. Что с приватностью и злоупотреблениями (домен — правоохранка)?**
RBAC + MFA, append-only аудит «кто/что/когда», биометрия шифруется и доступна от supervisor+,
human-in-the-loop на чувствительных выводах, security-гейт в CI. Анализ — только публичного
контента.

**В13. Какой объём тестов и как защищены от регрессий?**
246 backend-тестов + фронт; CI прогоняет unit+contract+сборку+security-гейт на каждый пуш;
правило — прошлые тесты не краснеют. Внешние вызовы замоканы.

**В14. Что если поменяется вёрстка t.me или отвалится коллектор?**
Логика парсинга изолирована и покрыта тестом на фикстуре; коллектор имеет `health()`; сбой
источника не роняет пайплайн (best-effort, dead-letter). Заменяется точечно.

**В15. Чем это лучше ручного мониторинга/простого классификатора?**
Не «бан одного ролика», а раскрытие **сети**: общие кошельки/каналы сшивают аккаунты в граф,
GDS показывает организатора, fingerprint ловит перезаливы схемы. Плюс объяснимый, юридически
защитимый балл и доказательная база.

## 8. Ограничения и развитие

- **Сейчас (прототип):** AI на внешних API (публичные данные); Money Flow — Ethereum (Etherscan);
  Telegram — публичные каналы; реестр — импорт CSV/allowlist.
- **Дальше:** self-hosted AI (vLLM/Whisper/биометрия) для полного on-prem; TRON-клиент для
  USDT-TRC20; Telethon-коллектор для приватных каналов; live-API регулятора; KMS для секретов,
  TLS на периметре, Ed25519-подпись доказательств.
