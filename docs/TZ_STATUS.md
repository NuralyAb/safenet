# SafeNet KZ — статус по минимальному ТЗ

**ТЗ (минимум):** постоянный сбор и анализ видео из Instagram/TikTok и др.; признаки
незаконного игорного бизнеса, финансовых пирамид и мошенничества; анализ видео,
аудио, текста, субтитров, визуальных маркеров; паттерны (нелицензионные казино,
«гарантированный доход», агрессивные инвест-призывы, реферальные схемы); риск-оценка,
объяснения, приоритизация для проверки.

Вывод: **ядро ТЗ уже построено.** Риск-движок прямо реализует факторную модель ТЗ
(`risk_engine.py`). Основные дыры — не в анализе, а в (1) *постоянстве* сбора и
*обнаружении новых* объектов, (2) переходе на on-prem модели, (3) проверке лицензий
по реестру.

Легенда: ✅ готово · 🟡 частично / каркас есть · ⛔ нет / нужно сделать

## 2. Что готово (можно показывать)

- **Мульти-сорс сбор.** Фреймворк коллекторов с реестром адаптеров: YouTube/TikTok/
  Instagram — реальная выгрузка через yt-dlp; Telegram — каркас; WhatsApp — корректно
  помечен как неподдерживаемый (E2E-шифрование). `collectors/`.
- **Чейн-оф-кастоди.** Оригиналы хешируются (SHA-256) и кладутся в WORM-бакет на
  этапе сбора; SSRF-guard. Это инвариант проекта и юридическая опора.
- **Мультимодальный конвейер.** `collect → process → fingerprint` на Celery с
  идемпотентностью, ретраями и dead-letter (`tasks.py`). Извлечение аудио+кадра
  через ffmpeg (`media.py`).
- **NLP-признаки.** 4 булевых фактора из текста, русский промпт, защищённый разбор
  JSON, fail-safe в False (`claims.py`). LLM извлекает **факты**, не ставит балл.
- **Детерминированный риск-движок.** Веса прямо из ТЗ (financial_promises 25,
  referral 20, known_scheme 20, suspicious_links 15, gambling 10, infra 10), уровни
  угрозы, рекомендация, разбивка с доказательствами (`risk_engine.py`,
  `investigation.py::risk_signals`).
- **Scam fingerprint.** Композитный отпечаток (текст-вектор + жёсткие идентификаторы)
  и поиск похожих в Qdrant → фактор «повтор схемы» (`fingerprint.py`).
- **AI Investigator (нарратив).** LLM пишет краткий отчёт строго по фактам и **не**
  присваивает риск числом (`investigation.py`).
- **Провайдерная абстракция AI.** OpenAI / Anthropic / local за единым интерфейсом —
  на прод можно свапнуть на self-hosted (`services/ai/`).
- **Тесты** на все ключевые модули (`backend/tests/`).

## 4. Что нужно сделать до сдаваемого MVP

Приоритет — закрыть именно те пункты ТЗ, что сейчас 🟡/⛔.

### Tier 0 — обязательно для слова «постоянный» в ТЗ
1. **Планировщик сбора (Celery beat).** Периодический обход watchlist'а объектов;
   расписание + дедуп по SHA-256 (идемпотентность уже есть). `celery_app.py`/новый
   `schedule.py`.
2. **Watchlist объектов.** Таблица отслеживаемых аккаунтов + API на добавление/снятие.
   Сейчас цель передаётся в `ingest()` вручную.
3. **Обнаружение новых объектов.** Поиск по ключевым словам/хэштегам (казино, инвест,
   «доход») вместо только известных `@handle`. Это отдельный режим коллектора —
   сейчас его нет, а ТЗ подразумевает «что происходит в сети», а не «проверь аккаунт».

### Tier 1 — закрыть мультимодальность ТЗ
4. **Субтитры + OCR экранного текста.** Тянуть субтитры yt-dlp; OCR кадра (на видео
   часто текст «гарантирую 30%», номер Telegram). Сейчас берётся только caption.
5. **Проверка лицензии по реестру.** `has_license` → реальная сверка с реестром РК,
   чтобы утверждать «**не**лицензионное казино», а не «нет упоминания лицензии».
   Без этого слово «незаконный» в ТЗ висит в воздухе.
6. **Очередь триажа.** Экран/эндпоинт «объекты на проверку», отсортированный по риску,
   с диспозицией аналитика (подтвердить/отклонить/в наблюдение). Балл и рекомендация
   уже есть — нужен рабочий процесс поверх.

### Tier 2 — качество и прод
7. **Снижение false positive.** Пороги, калибровка, «почему сработало» на каждый
   фактор (важнее для госоргана, чем новые фичи: ложная тревога убивает доверие).
8. **On-prem модели.** Подключить локальные Whisper / vision-детектор / эмбеддинги
   вместо OpenAI (`local_provider.py` — сейчас заглушки). Прототип на внешних API
   допустим **только на синтетике** (инвариант), прод — self-hosted.
9. **Обученный детектор казино/слотов** вместо LLM-тэггинга (`senior-computer-vision`).
10. **Telegram-коллектор** — дописать Telethon (`platforms.py`).

### Демо (1 шаг сверх ТЗ, дёшево — граф уже есть)
11. **От видео к сети.** В выдаче показывать не список роликов, а кампанию:
    «247 публикаций → 38 аккаунтов → 1 вероятная сеть → приоритет CRITICAL».
    Прямо усиливает требование ТЗ о приоритизации (`graph_builder.py` уже есть).

## 5. Короткий вывод

ТЗ закрыто примерно на **70%**: весь анализ (мультимодальный конвейер, признаки,
детерминированный риск с объяснениями) построен и протестирован. До сдаваемого MVP
ключевое — сделать сбор **постоянным и проактивным** (Tier 0), добить субтитры/OCR и
проверку лицензии (Tier 1), и дать аналитику **очередь на проверку**. On-prem модели
и детектор — отдельный, более крупный кусок (Tier 2), но прототип на внешних API
допустим на синтетике.
