# SafeNet KZ — демо-runbook для питча

Пошаговый сценарий для живой демонстрации на хакатоне. Проверено end-to-end:
login → расследование (Temporal) → граф → Money Flow (реальный on-chain) → триаж.

---

## 0. Подготовка стенда (за 10 минут до выступления)

```bash
# 1. Поднять стек
make up                       # docker compose up -d (12 сервисов)

# 2. ВАЖНО: после правки .env (ключи) контейнеры надо ПЕРЕСОЗДАТЬ, а не restart —
#    docker compose restart НЕ перечитывает env_file.
docker compose up -d --force-recreate backend collector-worker processing-worker

# 3. Применить миграции
make migrate                  # alembic upgrade head  (должно дойти до 0010)

# 4. Засеять демо-данные с известным паролем и демо-сетью
docker compose exec -e SafeNet KZ_DEMO_PASSWORD=demo-pass-1234 backend \
  python -m scripts.seed_demo --with-demo-network
```

> Без `--with-demo-network` сид создаёт **только пользователей** (принцип «без мок-данных»).
> Флаг поднимает синтетическую сеть из 3 аккаунтов + реальный on-chain кошелёк для Money Flow.

### Учётные данные демо
- **Аналитик:** `analyst-1` / `demo-pass-1234`
- **TOTP:** секрет печатается при сиде (`ENROL TOTP: otpauth://…`) — заведи в Google Authenticator заранее.
- Супервайзер: `supervisor-1` (пароль печатается при сиде) — для действий, требующих роли supervisor.

### Адреса
- Фронтенд: http://localhost:5173
- API + Swagger: http://localhost:8000/docs
- Neo4j Browser: http://localhost:7474

### Проверка готовности (smoke-тест одной командой)
```bash
docker compose exec -T backend python -c "
import httpx, pyotp
b='http://localhost:8000/api/v1'; otp=pyotp.TOTP('ВСТАВЬ_TOTP_СЕКРЕТ').now()
h={'Authorization':'Bearer '+httpx.post(b+'/auth/login', data={'username':'analyst-1','password':'demo-pass-1234','client_secret':otp}).json()['access_token']}
print('money-flow:', httpx.get(b+'/graph/money-flow/@fast_profit', headers=h).json()['boundary']['reached'])

# Ожидаемо: money-flow: exchange
```

## 2. Сценарий живого демо (вкладка за вкладкой)

> Цель: показать путь от аккаунта к деньгам и к сети. Каждый шаг — одна мысль.

### Шаг 1. Вход
Логин `analyst-1` + код из Authenticator. **Реплика:** «Двухфакторка обязательна — это инструмент для следователей».

### Шаг 2. Расследование (вкладка «Анализ → Расследование»)
1. Выбери `@fast_profit`, нажми **«Расследовать»**.
2. Через пару секунд — отчёт: риск **62 / MEDIUM**, 5 признаков, разбивка по 6 факторам.
3. **Реплика (ключевая):** «Балл считает детерминированный движок, не LLM. Вот этот вклад — за обещание доходности, и он привязан к конкретному доказательству. Это защитимо при ручной и юридической проверке».

### Шаг 3. Граф сети (вкладка «Сеть → Граф сети»)
1. Покажи кластер: аккаунты, общий кошелёк, Telegram.
2. **Реплика:** «Алгоритмы выделяют сообщества и центральные узлы — вероятных организаторов. 3 аккаунта связаны через один кошелёк — это не три дела, а одна схема».

### Шаг 4. Money Flow (вкладка «Сеть → Money Flow») — кульминация
1. Введи `@fast_profit`, нажми **«Проследить»**.
2. Покажется живая цепочка: `@fast_profit → 0x2b44…847a · ethereum → биржа · 0x28c6…` + плашка «Граница».
3. **Реплика:** «Это **реальные данные публичного блокчейна** через Etherscan. Деньги ушли на Binance. Мы честно ставим границу: дальше "биржа → банк" — это уже данные ведомства. Мы — мост, а не замена их систем».

### Шаг 5. Материалы (вкладка «Анализ → Материалы»)
1. Лента видео с риск-оценкой по каждому ролику, приоритет по убыванию риска.
2. **Реплика:** «Каждое видео оценивается отдельно тем же движком — это очередь на ручную проверку, приоритизированная по риску и охвату».

### Шаг 6. Справка / chain of custody (по желанию)
Выгрузка отчёта с SHA-256 манифестом. **Реплика:** «Каждый вывод привязан к хэшу оригинала в WORM-хранилище — доказательство неизменности».

## 3. Главные тезисы (чем отличаемся)

- **Детерминированный объяснимый риск-скор** — LLM извлекает факты, балл считает прозрачный движок; каждый балл → evidence_id. Не «чёрный ящик».
- **Chain of custody** — оригиналы хэшируются (SHA-256) в WORM при сборе; справка с манифестом.
- **Human-in-the-loop** — связи «один человек» только кандидаты, пока аналитик не подтвердит (`AUTO_CONFIRM_FORBIDDEN`).
- **On-prem by design** — весь AI за swappable-провайдером; в проде ноль внешних вызовов (`AI_PROVIDER=local`).
- **Money Flow с честной границей** — публичный on-chain до биржи, не претендуем на банковскую тайну.
- **Зрелость** — 226 backend + 6 frontend тестов зелёные; реальные интеграции (Etherscan V2, регуляторный реестр лицензий).

---

## 4. О чём говорить честно (если спросят)

- Локальные модели (vLLM/Whisper на своём GPU) — заглушка; прототип на внешних API через провайдер-абстракцию. **Только синтетика/демо через внешние API** — правило прототипа.
- Telegram-коллектор и часть on-chain — скелеты.
- Money Flow в демо использует синтетический аккаунт с **реальным** публичным адресом (не реальное дело).

## 5. Fallback (если упадёт сеть/API на сцене)

- Запиши экранную видеозапись всего пути заранее.
- CLI-демо on-chain без фронта: `python3 backend/scripts/demo_money_flow.py` — показывает реальный путь `кошелёк → Binance` напрямую.
- Граф и риск-скор работают **без интернета** (данные в Neo4j/Postgres) — даже без Etherscan демо живое до шага Money Flow.
