# SafeNet KZ — план внедрения и развития

## Что уже работает (MVP)

| Требование хакатона | Реализация |
|---|---|
| Обнаружение публикаций, эфиров, аккаунтов, групп | Проверка текста, скриншота (OCR + визуальные теги), транскрипта эфира, видео (STT + кадры), экспорта группы Telegram/WhatsApp; автономный поиск (Хантер, Радар), мониторинг аккаунтов |
| Скоринг с объяснением каждого срабатывания | Детерминированный балл по трекам; каждый признак — с цитатой, источником и способом маскировки; поправки видны отдельными строками |
| Уровни низкий / средний / высокий | Пороги 40 и 65, решение аналитика в очереди «Материалы» |
| Мультиязычность RU / KZ / транслит / сленг | Словарь RU+KZ, свёртка казахских букв, транслит-вид, сленг стримеров и пирамид |
| Мультимодальность (плюс) | Текст + скриншоты (OCR, визуальные теги) + речь эфиров и видео |
| Минимум ложных срабатываний | Гейты для каждого трека, смягчения (бесплатные конкурсы, банковские продукты, новости), реестр лицензий |
| Масштабируемость | Сотни материалов в секунду на ядро (правила), очередь Celery, граф Neo4j, Temporal |
| Графовый анализ | Аккаунты ↔ Kaspi-номера ↔ карты ↔ промокоды ↔ каналы ↔ домены; сообщества и центральные узлы |
| Метрики | precision / recall / FPR на четырёх выборках, включая независимую слепую; экран «Метрики и методика» |

## Этап 1 — пилот (1–2 месяца)

1. **On-prem модели вместо внешних API**: Whisper (речь), PaddleOCR (скриншоты, казахский), открытая
   LLM 7–14B через vLLM для LLM-помощника. Провайдер переключается одной настройкой (`AI_PROVIDER=local`),
   код конвейера не меняется.
2. **Разметка реальных данных пилота** аналитиками прямо в интерфейсе: решения «специалисту» и
   «ложное» пишутся в БД. Каждые 2 недели — пересчёт метрик и разбор ошибок. Слепой тест держим
   отдельно от выборки настройки.
3. **Источники**: публичные Telegram-каналы и группы (Telethon), Instagram и TikTok (публичные
   профили), импорт экспортов чатов от заявителей. WhatsApp — только экспорт, присланный участником
   (E2E-шифрование, см. `docs/collectors.md`).
4. **Реестры**: лицензированные букмекеры и лотереи (импорт `scripts/import_licensed_registry.py`),
   список выявленных пирамид АРРФР как известные схемы.

## Этап 2 — качество (2–4 месяца)

1. **Обучаемый классификатор поверх признаков**: логистическая регрессия или градиентный бустинг на
   векторе сил признаков. Сохраняем объяснимость (вклад каждого признака) и обучаемся на решениях
   аналитиков. Правила остаются гейтами.
2. **Эмбеддинги многоязычной модели** (например, multilingual-e5) для поиска перефразировок и
   повторов одной схемы в разных формулировках (отпечаток схемы в Qdrant уже есть).
3. **Детектор интерфейсов казино и экранов «вывода средств»** на скриншотах (YOLO / CLIP)
   вместо LLM-тегов.
4. **Разворот коротких ссылок** и цепочек редиректов в изолированной песочнице (SSRF-guard уже есть),
   сопоставление зеркал по WHOIS, хостингу и TLS-сертификатам.

## Этап 3 — масштаб (4–6 месяцев)

1. Горизонтальное масштабирование воркеров: правила — CPU, STT/OCR/LLM — пул GPU с приоритетом
   по охвату (риск × охват уже используется как ключ очереди).
2. Потоковая обработка: Kafka или Redis Streams перед Celery, дедупликация по SHA-256, отложенная
   тяжёлая обработка только для материалов со средним и высоким риском (каскад: дешёвые правила →
   OCR/STT → LLM).
3. Межведомственный обмен: экспорт «Аналитической справки» с цепочкой хранения (уже есть генератор
   пакета доказательств), API для профильных ведомств.

## Риски и как их снимаем

| Риск | Мера |
|---|---|
| Схемы меняют формулировки | LLM-помощник с проверкой цитат + регулярное обновление словаря по ошибкам из очереди; метрики по слепой выборке |
| Ложные обвинения | Система показывает признаки, а не вердикт; роли — кандидаты; каждое решение принимает человек и оно журналируется |
| Персональные данные | Маскирование карт, минимальный срок хранения, on-prem, разграничение ролей (RBAC + MFA) |
| Блокировки сбора | Мультиисточник, импорт экспортов, ручная загрузка скриншотов |
